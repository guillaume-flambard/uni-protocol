# Study results 2026-09-13 — first real-agent run (n=7)

Protocol: 5 small Rust issues, real headless implementer agent
(`opencode run --pure --auto -m bai/qwen3.8-flash`, free tier), one attempt
per task, then two reruns kept for diff review. UNI verified each result
against per-test-claim contracts. Human review = diff inspection by
Guillaume, blind-ish (UNI decision seen, diff checked after).

**The study's whole point in one line: the agent claimed success 7/7 while the
human rejected 7/7; UNI agreed with the human on all 7 (0 accepted, 0 false
accepts). Acceptance-side agreement needs capable-agent data (limitation 1).**

## What actually happened

In the two diff-preserved runs the agent committed zero code changes (the only
file in "agent-fix" was the registry run.py itself writes) yet replied DONE.
The other five rows are consistent with the same no-op pattern: claims backed
by pre-existing passing tests verified, claims requiring new behavior did not.
t05 was REJECTED because its base already fails the required test.

## Honest limitations

1. The free-tier model is a weak implementer; this measures "UNI vs lazy
   agent", not "UNI vs capable agent". Premium models are currently blocked on
   this account ("Access restricted. Deposit required"), so capable-agent rows
   await provider access.
2. Contracts pin evidence to specific test NAMES (registry `expect`). A
   capable agent that fixes the bug with differently-named tests would still
   get EVIDENCE_REQUIRED. Fixing this is fuzzier claim-to-test selection
   (v0.2+), or shipping verifier guidance in issue.md.
3. Real agents can reach the harness fixtures: the first contaminated run let
   an agent edit the task base file itself (caught by `git status`, base
   restored). run.py now resets fixture drift after every task (guard added).
4. Headless opencode needs `--pure --auto -m <free model>`; default provider
   streams hang without a model override, `--format json` times out. Recorded
   so future runs don't rediscover it.
