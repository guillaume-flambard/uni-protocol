# Stale Evidence Benchmark, 2026-09-14

100 manufactured drift scenarios. No model involved. `run.py` builds each
scenario, proves it with UNI, applies one drift, and then asks three oracles on
the delivered revision. Ground truth is written by the scenario author.

Reproduce: `cargo build --release && python3 run.py` (writes `results.csv`).

The 86 percent is not a miss. Every category where detection is possible is at
100 percent. The single category UNI accepts, a weakened trusted registry, is
one it cannot defend automatically: the registry is the trust root, so the run
names the change (100 percent) and a human decides. The number to read is
70 scenarios where the artifact no longer satisfied the claims, of which a plain
exit-code CI called 50 green and a result cache called all 70 green.

## What the oracles model

- **exit-code CI**: a workflow that runs its pinned commands and is green when
  they exit 0. It catches a broken artifact when a test covers it (the two
  artifact and subject rows), and nothing else.
- **cached CI**: a result cache, a test-impact analysis, or a path-filtered
  workflow that reuses the previous green unless the tests or the contract
  changed. It misses all 70, because the drift is never in a file its key
  watches.
- **UNI**: records expected output, watched content, per-file and whole-artifact
  hashes, frozen files, the registry, the authorization and the platform, and
  refuses to carry a proof across any of them.

## What it shows

Ordinary verification fails in two families, and neither is about a model being
careless:

1. **The check still exits 0, the proof is gone.** A test weakened to
   `0 passed`, a skipped suite, a frozen file that changed, a claim with no
   verifier, an authorization that now selects nothing. Exit codes cannot see
   this class; output expectation and content binding can.
2. **Freshness and provenance are not modelled at all.** A proof from another
   commit, another platform, or another month is indistinguishable from a live
   one unless the verification context is part of the proof.

The result also draws the limit honestly: a weakened trusted registry is not
detectable by the machine that trusts it. That is a review boundary, and the
protocol's job is to name it loudly, which it does in 100 percent of the cases.

## Caveats

- The drift is manufactured, so the benchmark measures detection machinery, not
  real-repo incidence. Its claim is that these classes exist and are structural,
  not that they occur at a given rate in the wild.
- Platform drift is simulated by editing the stored proof, which is exactly what
  a different machine would produce; it is not a second real machine.
- The baseline models are intentionally simple and stated above. A CI that
  re-runs everything and compares output would land closer to UNI on family 1;
  it would still miss family 2, and it would not know which claims it covered.
